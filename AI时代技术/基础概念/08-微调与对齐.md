# 微调与对齐：SFT / LoRA / RLHF / DPO
> 一句话：**预训练让模型「会说话」，SFT 让模型「会按要求做事」，偏好对齐让模型「说得让人满意」；LoRA 解决「改得起」，DPO/RLHF 解决「改得对」。**
> 定位：微调改的是**模型的行为与风格**，不是可靠的知识注入手段——动态事实仍然优先交给 RAG。

## 一、三段式训练全景
```
海量无标注语料                指令-回答数据               偏好对比数据
      │                          │                          │
  预训练 Pretrain  ──────▶  SFT 监督微调  ──────▶  偏好对齐（RLHF / DPO / GRPO）
  next-token 预测            学会遵循指令格式          学会「哪种回答更好」
      │                          │                          │
   基座模型 Base            指令模型 Instruct          对齐模型 Chat / Reasoning
```
| 阶段 | 数据形态 | 目标 | 典型成本 |
|---|---|---|---|
| 预训练 | 万亿级 Token 纯文本 | 学会语言与世界知识 | 极高，通常不做 |
| SFT | 万~百万级 `(指令, 回答)` | 学会任务格式、语气、拒答方式 | 中 |
| 偏好对齐 | 万~十万级 `(问题, 优选, 劣选)` | 提升有用性、无害性、推理质量 | 中高 |
| 继续预训练 CPT | 领域纯文本（法律/医疗/代码） | 注入领域分布与术语 | 高，易遗忘 |

> 关键认知：**知识在预训练阶段进入参数，SFT/对齐主要塑造行为**。想让模型「知道昨天发布的政策」，微调既慢又不可靠，RAG 才是正解。

## 二、SFT：监督微调
### 1. 原理
标准的 next-token 预测，但**只在回答部分计算 loss**：
```
[system] 你是客服助手 [user] 怎么退货？ [assistant] 请在订单页点击……
└──────────── 输入，mask 掉不算 loss ────────────┘└──── 只对这部分算 loss ────┘
```
如果连 prompt 一起算 loss，模型会学会「复述用户问题」，指令遵循反而变差。

### 2. 数据比算法重要
1. **质量 > 数量**：几千条干净、风格一致的样本，往往胜过几十万条噪声数据；
2. **多样性**：任务类型、长度、难度、拒答场景都要覆盖，否则模型在没见过的任务上崩；
3. **格式统一**：必须严格使用目标模型的 chat template（角色标记、BOS/EOS），训练与推理不一致会出现「模型不会停」或「输出带角色前缀」；
4. **去重与污染检查**：训练集混入评测集会造成分数虚高，用 n-gram 重叠检测清理；
5. **蒸馏数据要谨慎**：用强模型生成的数据有效，但会继承其错误与风格，且可能违反服务条款。

### 3. 常见问题
- **灾难性遗忘**：只训单一任务，通用能力下降。对策：混入通用指令数据、降低学习率、少训几轮；
- **过拟合**：loss 持续下降但评测变差，通常 1~3 epoch 就够，及早停；
- **长度偏置**：SFT 数据回答普遍很长，模型会变得啰嗦；
- **学会拒答过度**：安全样本比例过高，正常问题也开始拒绝。

## 三、LoRA：让微调变得便宜
### 1. 核心假设
微调时权重的变化量 **ΔW 是低秩的**，不需要更新整个矩阵，只需学一个低秩分解：
```
W' = W + ΔW = W + (α / r) · B · A
W ∈ R^{d_out × d_in}   冻结
A ∈ R^{r × d_in}       随机初始化
B ∈ R^{d_out × r}      零初始化（保证训练起点 ΔW=0）
```
- `r`（rank）通常 8 / 16 / 32 / 64，越大容量越强、越容易过拟合；
- `α`（lora_alpha）是缩放系数，常用 `α = 2r`；
- 可训练参数量从 `d_in × d_out` 降到 `r × (d_in + d_out)`，7B 模型通常只训 0.1%~1%；
- 训练完可把 `BA` 合并回原权重，**推理零额外延迟**；也可以不合并，动态挂载多套 LoRA 做多租户。

### 2. 挂哪些层
经验顺序：`q_proj, k_proj, v_proj, o_proj` 必挂，效果不够再加 `gate_proj, up_proj, down_proj`（MLP 层）。全挂 + 较高 rank 效果最好，但显存和过拟合风险上升。

### 3. QLoRA
在 LoRA 基础上把**基座模型量化到 4bit** 再训练：
- **NF4（NormalFloat 4bit）**：按正态分布分位数量化，比均匀 int4 更适配权重分布；
- **双重量化**：对量化常数再量化一次，进一步省显存；
- **Paged Optimizer**：显存峰值时把优化器状态换出到 CPU，避免 OOM；
- LoRA 适配器仍用 bf16 训练，梯度精度不受影响。

效果：单张 24GB 显卡可以微调 7B~13B 模型，是个人与小团队的事实标准。

### 4. 其他 PEFT 方案
| 方法 | 思路 | 特点 |
|---|---|---|
| **LoRA** | 低秩旁路矩阵 | 生态最好、可合并、可多套切换 |
| **QLoRA** | 4bit 基座 + LoRA | 显存最省，训练略慢 |
| **Adapter** | 插入小瓶颈层 | 推理有额外延迟，逐渐被 LoRA 取代 |
| **Prefix / P-Tuning** | 学一段虚拟 Token | 参数量极小，但占用上下文、效果不稳定 |
| **全参微调** | 更新所有参数 | 上限最高、成本最高，通常只在有充足数据时用 |

### 5. 关键超参
- 学习率：LoRA 常用 `1e-4 ~ 2e-4`，全参 `1e-5 ~ 2e-5`（差一个量级）；
- epoch：1~3，指令数据重复多轮收益递减；
- batch size：用梯度累积凑等效 batch（如 32~128）；
- 序列长度：按数据分布设，过长浪费显存，过短会截断样本；
- 学习率调度：cosine + warmup 是稳妥默认；
- 显存优化：gradient checkpointing、FlashAttention、DeepSpeed ZeRO / FSDP。

## 四、偏好对齐：RLHF
### 1. 三阶段流程
1. **SFT**：先得到能正常回答的初始策略；
2. **训练奖励模型 RM**：对同一问题采样多条回答，人工标注优劣，用 Bradley-Terry 模型拟合「A 比 B 好」的概率；
3. **PPO 强化学习**：策略模型生成回答 → RM 打分 → 用 PPO 更新策略，同时加 **KL 惩罚**约束不要偏离 SFT 模型太远。

### 2. 为什么难
- 同时要跑 **4 个模型**：策略、参考模型、奖励模型、价值模型（critic），显存是 SFT 的数倍；
- PPO 超参敏感，训练不稳定，容易崩；
- **Reward Hacking**：模型学会讨好奖励模型（堆砌套话、过度自信、变长），而不是真正变好；
- 人工偏好数据昂贵且有标注者偏差。

## 五、DPO：绕开奖励模型
### 1. 核心思想
数学上可以证明：带 KL 约束的 RLHF 最优策略，存在一个**隐式奖励**与策略和参考模型的 log 概率比对应。于是可以跳过「训练 RM + PPO」，直接用偏好对做分类式训练：
```
L_DPO = -log σ( β·[log π(y_w|x) - log π_ref(y_w|x)]
                - β·[log π(y_l|x) - log π_ref(y_l|x)] )
```
- `y_w` 优选回答、`y_l` 劣选回答；
- `π_ref` 是冻结的参考模型（通常就是 SFT 模型），**DPO 仍然需要它**；
- `β` 控制允许偏离参考模型的程度，常用 0.1~0.5，越小越保守。

### 2. 相比 RLHF 的取舍
| 维度 | RLHF（PPO） | DPO |
|---|---|---|
| 需要奖励模型 | 是 | 否 |
| 需要 critic | 是 | 否 |
| 训练稳定性 | 差，调参难 | 好，接近普通监督训练 |
| 显存 | 高（4 模型） | 中（策略 + 参考） |
| 上限 | 更高，可在线探索 | 受限于离线偏好数据 |
| 工程复杂度 | 高 | 低 |

> DPO 不是「免费午餐」：它只能用**已有偏好数据**，缺少在线探索；数据分布外的场景容易过度优化，出现「偏好数据里没有的坏习惯」。

### 3. 后续变体
- **ORPO**：把 SFT 与偏好优化合成一步，不需要参考模型，省显存；
- **KTO**：只需要「好/坏」二元反馈，不需要成对比较；
- **SimPO**：用长度归一化的平均 log 概率做隐式奖励，去掉参考模型；
- **GRPO**：对同一问题采样一组回答，组内归一化算优势，**不需要 critic**，配合可验证奖励（RLVR）在数学、代码任务上效果突出，是推理模型训练的主流方案之一。

### 4. RLVR：可验证奖励
数学题有标准答案、代码有单元测试，这类任务可以用**规则判定**代替人工偏好：
- 优点：奖励客观、可无限采样、不易被 reward hacking；
- 缺点：只适用于结果可验证的领域，开放写作、客服话术无法直接套用；
- 训练信号稀疏（全对或全错），需要靠组内相对比较（GRPO）提供梯度。

## 六、微调还是 RAG：怎么选
| 需求 | 首选方案 | 原因 |
|---|---|---|
| 注入最新政策、私有文档 | **RAG** | 可实时更新、可溯源、无需重训 |
| 固定输出格式（JSON、工单话术） | **SFT / LoRA** | 格式是行为，靠示例最有效 |
| 统一语气、品牌风格 | **SFT / LoRA** | 少量高质量样本即可 |
| 提升特定领域推理 | **领域 SFT + RLVR** | 需要行为与策略层面的改变 |
| 模型总答错简单规则 | Prompt + Few-shot | 先排除提示词问题 |
| 知识频繁变动 | RAG + 定期重建索引 | 微调更新周期跟不上 |

决策顺序建议：**Prompt/Few-shot → RAG → LoRA → 全参微调 → 继续预训练**。每往下一层，成本与维护难度都显著上升。

> RAG 与微调是互补而非替代：常见组合是「微调教格式与话术 + RAG 供事实」。

## 七、评估与上线
1. **留出集**：训练/验证/测试严格分离，防止数据泄漏；
2. **回归评测**：微调后跑一遍基础能力（指令遵循、拒答、安全、长上下文），防止「专项变强、通用变傻」。具体评测方法见 Harness 笔记；
3. **A/B 对比**：同一条 prompt 分别打新旧模型，人工或裁判模型盲评；
4. **版本可追溯**：记录基座版本、LoRA rank、数据版本、超参、chat template，否则无法复现；
5. **灰度上线**：先小流量，监控幻觉率、拒答率、平均长度、成本；
6. **回滚预案**：LoRA 可多套并存，出问题直接切回旧适配器，比全参微调安全得多。

## 八、常见误区
1. ❌ 微调可以可靠注入新知识：模型更容易「学会自信地编」，事实更新仍应走 RAG；
2. ❌ 数据越多越好：低质、重复、单一风格的数据会让模型退化，质量与多样性优先；
3. ❌ LoRA 一定不损失效果：rank 太小、只挂 attention、数据不足时明显弱于全参；
4. ❌ LoRA 训练完必须合并：不合并可以动态加载多套，适合多租户；合并只是为了推理省事；
5. ❌ DPO 不需要参考模型：仍要 `π_ref` 算 logprob，只是省掉了 RM 和 critic；
6. ❌ RLHF 一定优于 DPO：取决于数据与场景，DPO 在多数团队的可复现性更好；
7. ❌ SFT 后 loss 低就说明模型好：loss 只衡量对训练分布的拟合，不代表指令遵循与安全性；
8. ❌ chat template 可以随便改：训练与推理模板不一致是最常见的「模型变傻」原因之一；
9. ❌ 微调可以替代提示词工程：很多问题用清晰指令 + Few-shot 就能解决，微调是最后手段。
