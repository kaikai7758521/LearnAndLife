# AI Agent 核心名词盘点笔记（原理+分层+常见Agent一览）
> 核心分层关系：**Tool（原子能力）→ Skill（封装流程）→ Harness（运行编排底座）→ Agent（完整智能体）**
> 经典公式：**Agent = LLM 大脑 + Harness 运行框架（记忆/循环/安全/工具调度）**

## 一、核心名词与原理细节
### 1. Agent（智能体）
**定义**：以大模型为推理核心，具备感知、规划、工具调用、状态记忆、自主迭代闭环，朝着目标持续行动的自治系统，区别于普通一问一答的对话模型。
**核心循环：ReAct（Reason + Act，推理-行动循环）**
1. 观察（Observe）：读取用户目标、历史记忆、工具返回结果、环境信息
2. 推理（Reason）：LLM 判断当前状态、思考下一步动作、选择工具、生成调用参数
3. 行动（Act）：交给Harness执行工具调用、代码执行、API请求
4. 反馈（Observe again）：拿到执行结果，回到推理，直到目标完成/失败终止
**关键组件**：LLM推理引擎、记忆系统、规划器、工具集、安全护栏（Guardrail）、状态机。
**和普通Chat模型区别**：Chat是被动响应单轮请求；Agent是目标驱动、多步自主执行，能自己决定要不要继续调用工具。

### 2. Tool（工具）
**定义**：原子、最小粒度的可调用函数/接口，是Agent的“手脚”，只负责执行单一、确定性动作，**本身不带业务逻辑和规划能力**。
**原理**：用JSON Schema描述入参、出参，LLM输出符合规范的函数调用指令，由Harness调度执行。
**常见Tool例子**：搜索引擎、计算器、数据库查询、文件读写、代码执行器、邮件发送、API请求、浏览器访问。
**特点**：无状态、单一职责；可被多个Skill、多个Agent复用；失败后由上层重试或调整策略。

### 3. Skill（技能）
**定义**：面向业务任务、封装好的**可复用任务单元**，由一组Tool + 固定流程 + 约束Prompt + 校验规则组合而成，解决“重复写复杂prompt、流程不稳定”问题。
**原理**：把一个标准化SOP打包：前置校验→按顺序调用多个工具→结果校验→异常分支处理→输出格式化。
> 简单区分：Tool = 一个API；Skill = “用多个工具完成一件完整业务事”
例子：
- 【财报解读Skill】：调用搜索→拉取财报PDF→RAG检索→抽取指标→生成对比表格
- 【工单处理Skill】：查询客户信息→生成回复→发送邮件→写入工单系统
**特点**：业务友好、可灰度更新、可独立测试；Skill内部可以包含子Skill；是企业落地Agent最常用的抽象层。

### 4. Harness（Agent Harness，智能体运行基座/脚手架）
**定义**：包裹在LLM之外的整套运行时框架，**不属于模型本身**，负责驱动整个ReAct循环，是Agent的“操作系统”。
> 行业一句话：If you are not the model, you are the harness. 不是模型的部分，都是Harness
**Harness核心模块（原理细节）**
1. 循环驱动器：反复执行 LLM调用 → Tool执行 → 结果回填
2. 状态与记忆管理层：短期对话上下文、长期向量记忆、任务进度快照
3. 工具调度层：Schema校验、沙箱隔离、权限鉴权、并发、超时、重试
4. 安全护栏Guardrail：危险操作拦截、人工审批节点、输出过滤、白名单
5. 可观测层：日志、trace、耗时、调用记录、成本统计
6. 编排与委托：支持拆分子Agent、任务分发
**典型Harness**：LangChain、LlamaIndex、Microsoft Agent Framework、Claude Code Harness、Google Antigravity

### 5. LSP（Language Server Protocol，语言服务器协议）
> 注：在Agent（尤其是编码Agent）生态里高频出现，是编码Agent和代码编辑器交互的核心标准协议，Devin、Aider、Claude Code等编码Agent大量依赖LSP。
**定义**：LSP是一套**编辑器 ↔ 语言服务器**之间的标准化JSON-RPC通信协议，解耦编辑器UI和语言分析能力。
**核心原理**
1. 分离两层：前端（编辑器/Agent客户端）、后端（Language Server，语言服务进程）；
2. 通信基于JSON-RPC，走stdio、socket等通道；
3. 语言服务器独立进程，负责理解代码AST、符号、类型、引用、诊断信息；
4. 客户端（可以是VSCode，也可以是编码Agent）向Server发送请求，Server返回代码语义信息。

**LSP能提供的能力（编码Agent非常依赖）**
- 符号查找：go-to-definition 跳转到定义、find-references 查找所有引用
- 代码诊断：语法错误、lint告警
- 补全、hover提示、重命名（rename）
- 文档符号列表、workspace范围搜索符号

**在Agent场景下的价值**
普通Agent只能读原始文本文件；接入LSP之后，Agent不再只是“看字符串”，而是**理解代码的语义结构**，知道变量、函数、类之间的依赖关系，大幅减少改代码改错引用、看不懂项目结构的幻觉。
> 区分：LSP本身不是Agent，也不是Tool；它是一套**语义查询接口标准**，编码Agent通常封装一个LSP Client作为内部Tool/Skill，用来读取项目语义。
例子：Aider、Devin在分析大型代码库时，会启动对应语言的LSP Server（gopls、tsserver、pyright等），调用LSP接口获取符号信息，而不是单纯全文检索。

### 配套高频名词补充
#### ReAct
推理行动范式，是当前绝大多数Agent的基础循环，把思维推理和工具调用交错进行，解决LLM幻觉、无法获取实时信息的痛点。

#### RAG（检索增强生成）
常作为Skill内部的能力，把私有文档向量化检索，给Agent提供外部知识库；RAG本身不是Agent，但几乎是行业Agent标配Skill。

#### Memory（记忆）
三层经典划分：
- 短时记忆：本轮对话上下文窗口
- 情景记忆Episodic：历史任务记录、过往交互（向量库）
- 程序记忆Procedural：即Skill，记住“怎么做这件事”的流程

#### Planner（规划器）
Agent里的规划模块，分两种：
1. 大模型原生规划：LLM自己输出计划（适合简单任务，不稳定）
2. 分层规划：先拆成子任务清单，子任务再交给子Agent/Skill执行（适合长任务）

#### Sub-Agent / Multi-Agent（多智能体）
主Agent把复杂任务拆解，委派给专门的子Agent（编码Agent、检索Agent、评审Agent），分工协作；Harness负责路由、结果合并、冲突协调。

#### Guardrail（安全护栏）
Harness内置校验层，在调用工具前、模型输出后拦截高危动作：删除文件、高危shell、泄露敏感数据、越权访问。

## 二、常见Agent分类及其特点
> 分两类视角：经典AI理论分类 + 当前大模型时代工程落地分类

### 【经典AI理论5类（教科书分类）】
1. **简单反射智能体 Simple Reflex Agent**
特点：只根据当前输入+固定规则响应，**无记忆、无历史感知**，不会规划。
局限：只能处理确定、无状态场景。例子：关键词自动回复、简单规则机器人。

2. **带模型的反射智能体 Model-based Reflex Agent**
特点：维护一个环境状态模型，记住上一轮状态；能处理部分观测、非即时反馈场景。
例子：简单监控告警机器人。

3. **目标导向Agent Goal-based Agent**
特点：以目标为核心，主动搜索多条行动路径、预判结果、选择能靠近目标的路径，具备基础规划。
适合：路径规划、任务调度。

4. **效用导向Agent Utility-based Agent**
特点：不止看“是否达成目标”，引入效用函数评估方案好坏；支持多目标冲突权衡（成本、速度、风险）。
适合：资源分配、决策推荐、投资辅助。

5. **学习型Agent Learning Agent**
特点：内置学习模块，从历史交互里改进策略；可以自动优化Skill、调整规划策略。
局限：落地难度高，当前LLM Agent大多是“few-shot学习”而非持续在线学习。

### 【工程落地：LLM时代主流Agent】
1. **对话式Agent Conversational Agent**
代表：通用对话助手、客服Agent
特点：以交互为主，目标是问答、引导；工具能力轻；自主性弱，依赖用户持续引导；记忆以对话历史为主。

2. **工具调用单步Agent（Tool Calling Agent）**
代表：LangChain基础ReAct Agent
特点：基础ReAct循环，LLM自主选工具；适合查询、计算、简单数据处理；**没有长任务规划能力，任务太长容易跑偏、循环发散**。

3. **规划型Agent Planner Agent**
代表：AutoGPT、BabyAGI
特点：先输出完整任务计划，拆成子任务清单，逐个执行、复盘进度；适合长流程、复杂目标；痛点：容易过度规划、幻觉导致计划不可行，资源消耗高。

4. **Act-Plan Agent（行动-规划智能体）【目前工程能力最强】**
代表：Plan-and-Solve、ActPlan、部分改进版BabyAGI，也是很多编码Agent的内部循环范式
特点：**双分支交替：规划阶段(Plan) + 执行阶段(Act)，和原生ReAct有明显区别**
- Plan阶段：基于当前全部状态，更新全局任务计划、调整子任务优先级、识别失败/阻塞点；计划会动态修改，不是一次性写死；
- Act阶段：只挑选当前计划里的**下一步子任务**执行（调用工具、读写环境）；
- 执行拿到反馈后，回到Plan阶段重新评估、修订计划，而不是每次只思考单步动作。
> 和普通ReAct对比：ReAct是“一步一思考”，偏向局部贪心决策；Act-Plan 显式维护一份独立计划，全局视角更强。
优势：长任务稳定性更好，不容易无限绕圈；方便人类查看、干预、修改计划；适合多步骤项目、大型代码改造、复杂调研。
短板：每一轮规划都要消耗额外token，成本更高；计划本身依然会产生幻觉，如果计划错了，后续执行全部跑偏。

5. **编码Agent Coding Agent**
代表：Claude Code、Aider、Devin
特点：强文件系统、shell、git工具集；Harness专门做沙箱、代码执行、diff提交；自带代码评审、测试执行闭环；大量集成LSP Client，获取代码语义符号；对Harness沙箱安全要求极高。

6. **多智能体 Multi-Agent System**
代表：AutoGen、CrewAI
特点：角色分工（产品、开发、测试、评审）；Agent之间互相对话、委派任务、结果校验；适合复杂项目、文档协作、联合数据分析；难点是通信协议、冲突处理、成本膨胀。

7. **企业数字员工Agent（业务Skill化Agent）**
代表：内部RPA+LLM融合Agent、工单Agent、财务对账Agent
特点：高度绑定业务SOP，大量使用封装好的Skill；工具是企业内部系统（OA、ERP、数据库）；Harness重点做权限审批、审计、可追溯；自主性可控，很多节点需要人工确认。

8. **自主Agent Autonomous Agent**
代表：早期AutoGPT类项目
特点：最少人工干预，设定目标后持续自主循环；风险最高，容易无限循环、越权操作；现在工业落地普遍加人工闸门、最大轮数限制。

## 三、层级对照
| 层级 | 名词 | 一句话定位 |
|---|---|---|
| 原子能力 | Tool | 可调用函数，做一件小事 |
| 业务单元 | Skill | 多个Tool+流程，完成一个标准化业务任务 |
| 语义接口标准 | LSP | 给编码Agent提供代码AST/符号语义查询的通信协议 |
| 运行底座 | Harness | 循环、记忆、沙箱、调度、安全，让LLM能动起来 |
| 完整实体 | Agent | LLM + Harness + Skill + Tool + 目标闭环 |

## 四、常见误区
1. 有Tool调用 ≠ Agent：很多只是带函数调用的Prompt工作流，没有自主循环、状态跟踪，不属于Agent；
2. Skill不是Prompt：Prompt是一次性指令，Skill是可版本管理、可复用、带异常分支的能力包；
3. Harness不是框架SDK的名字：LangChain是SDK，你在LangChain上写出来的整套运行时，才是你的Harness；
4. Agent不是越自主越好：工业落地优先可控，高自主一般只在隔离沙箱环境使用；
5. LSP ≠ 代码补全：LSP是协议，补全只是它的能力子集；Agent用LSP核心目的是读懂代码依赖关系；
6. Act-Plan ≠ Planner Agent：经典Planner是一次性生成全量计划；Act-Plan是**规划-执行交替迭代，计划动态更新**。
