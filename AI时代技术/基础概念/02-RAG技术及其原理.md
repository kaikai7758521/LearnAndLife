# RAG技术及其原理
> 前置一句话重点：**RAG 不是一种独立大模型，它是一套「检索 + LLM」的应用架构；LLM 是里面负责生成的大脑，RAG 给这个大脑外挂一个可随时更新的知识库**。
> 可以和上一篇 Agent 笔记联动：RAG 经常封装成 Agent 的一个 Skill。

## 一、基础定义与原理
### 普通 LLM（原生大语言模型）
**定义**：经过海量文本预训练、权重固化的生成模型，所有知识都被编码在模型参数（权重）里面，这部分知识也叫**参数化知识（Parametric Memory）**。
**工作流程**
用户提问 → 模型读取上下文窗口内的对话历史 → 依靠训练阶段学到的参数知识，自回归输出回答。
- 它不知道“外部文档”；它只知道训练时见过的文本分布。
- 知识冻结在**训练截止时间**，截止之后发生的新事情、你的私有文档，它都没有天然认知。
- 回答是概率生成，优先保证流畅，不一定保证事实正确，这就是幻觉的来源。

### RAG（Retrieval-Augmented Generation，检索增强生成）
**定义**：在 LLM 生成之前，增加一个独立检索链路，从外部知识库拉取相关片段，把片段和用户问题一起塞进 Prompt，让 LLM**基于检索到的证据来写答案**；知识来源 = 参数知识 + 外部非参数化知识库（Non-parametric Memory）。
**两大阶段**
1. **离线索引阶段（准备知识库）**
文档解析 → 文本分块（Chunk）→ Embedding 向量化 → 存入向量库（也可以搭配 BM25 关键词检索），建立可检索索引。
2. **在线问答阶段（推理时）**
用户提问 → 问题向量化 → 在向量库检索 Top-K 相关片段 → 把【用户问题 + 检索片段】组装成增强后的 Prompt 喂给 LLM → LLM 依据给到的参考材料输出回答，支持标注引用来源。

> 通俗类比：
> - 纯 LLM：闭卷考试，全凭脑子里训练记住的内容作答，记不清就容易编。
> - RAG：开卷考试，拿到题目先翻指定参考书，再照着书上内容写答案。

## 二、核心维度对比
|对比维度|普通 LLM（无RAG）|RAG 系统（检索增强LLM）|
|---|---|---|
|知识存储位置|全部在模型权重（参数内）|权重 + 外部向量知识库（分离）|
|知识时效性|固定，卡在训练截止日，新信息无法感知|随时新增、修改、删除文档，知识可以实时更新，不用重训模型|
|私有数据支持|原生不认识企业文档、内部规范、私人资料|天然对接私有PDF、数据库、手册、工单等内部资料|
|幻觉风险|高，未知领域很容易编造事实|显著降低，但**不能彻底消除**（检索到错材料、模型无视材料依然会幻）|
|答案溯源|很难，无法给出材料来源|可以输出引用片段、文档链接、页码，可校验、可审计|
|修改知识成本|极高，改事实通常需要微调/重新训练，成本贵、周期长|很低，直接更新知识库文档即可，无需动模型权重|
|上下文上限|受限于模型原生上下文窗口|理论上知识库可以无限大；但**单次送入LLM的检索片段依然受窗口限制**|
|擅长任务|通用创作、逻辑推理、翻译、脑洞、开放式对话|企业问答、文档答疑、知识库客服、法规/手册查询、事实类问答|
|额外组件|只需要LLM服务|Embedding模型、向量数据库、检索器、分块/清洗链路、重排器（高级RAG）|
|延迟&成本|简单，单轮LLM调用|更高，多了向量检索、Embedding调用，token消耗更大|

## 三、各自的优势、短板
### ✅ 普通 LLM
优势：
1. 部署简单，链路短、延迟低；
2. 强泛化、创意、抽象推理、多轮自由对话；
3. 不依赖外部文档，适合开放式、创作类任务。

短板：
1. 知识过时；
2. 私有内容、小众领域知识缺失；
3. 事实类问题幻觉严重，答案不可溯源；
4. 更新事实代价巨大，微调有遗忘风险。

### ✅ RAG
优势：
1. 知识解耦，文档随时更新，低成本维护；
2. 能接入私有、涉密、内部业务资料；
3. 事实类回答更可控，支持引用溯源，方便审计；
4. 不需要频繁微调大模型，适合企业落地。

短板：
1. 依赖检索质量：召回不准、召回无关垃圾片段，答案直接出错（RAG的典型失败叫“检索污染”）；
2. 增加系统复杂度：要维护向量库、分块策略、重排、去重；
3. 无法提升模型本身底层推理能力，复杂数学、长链逻辑依然靠LLM本身；
4. 窗口瓶颈：一次能塞给模型的参考材料有限，超长文档需要复杂路由。

## 四、误区
1. ❌ 误区：RAG 是一个新模型
✅ 正解：RAG 是架构范式，底层依然在用 LLM；你可以把同一个 LLM 接入 RAG，也可以直接裸用。
2. ❌ 误区：RAG 可以完全消灭幻觉
✅ 正解：RAG 是** grounded（接地）**手段，大幅减少事实幻觉；但如果检索到错误文档、模型强行发挥、Prompt约束弱，依旧会产生幻觉。
3. ❌ 误区：有了RAG就不需要微调
✅ 正解：二者互补。RAG适合动态事实、外部资料；微调适合让模型学会固定格式、固定风格、领域话术。
4. ❌ 误区：RAG=向量搜索
✅ 正解：向量检索只是RAG其中一个模块；完整RAG包含数据清洗、分块、embedding、召回、重排、prompt组装、生成校验一整条链路。

## 五、和Agent体系的联动
RAG 经常封装成一个**Skill**，给 Agent 使用：
Agent 收到用户需求 → 判断需要查知识库 → 调用 RAG Skill（执行检索+拿到参考材料）→ 再基于材料继续规划、调用其他 Tool、输出结果。
> 区分：
> - 裸LLM：单纯对话生成
> - RAG：文档检索增强问答系统
> - Agent：带循环规划、Tool/Skill调度的自治智能体，RAG是它可选的一个能力单元

## 六、简单选型参考
- 写文案、头脑风暴、翻译、自由聊天、通用推理 → 直接用普通LLM
- 查公司制度、产品手册、历史工单、论文、私有文档、需要引用来源的事实问答 → RAG优先

## 七、Naive RAG / Advanced RAG / Modular RAG 的区别
- **Naive RAG（朴素 RAG）**：最简原型，只有「分块→向量化→向量召回→拼 prompt」，链路短、好上手，但召回质量不稳定。
- **Advanced RAG（增强 RAG / 高级 RAG）**：在朴素 RAG 上加各类优化模块（重排、查询改写、多检索融合、过滤），**不改变主链路结构**，是在原有流水线里插增强环节。
- **Modular RAG（模块化 RAG）**：把 RAG 拆成大量可插拔、可路由的独立模块，增加调度器 / 规划器，**动态选择检索策略、检索源、后处理逻辑**，和 Agent 思想高度融合。
