# Variables and Types

JavaScript is a dynamically typed language: variables themselves have no type, only values do. There are three declaration keywords — `var`, `let`, and `const` — and understanding how they differ is the first step toward writing good JavaScript.

> [!NOTE]
> This note covers modern syntax after ES2015; both browsers and Node.js support it.

## Three Ways to Declare Variables

| Keyword | Scope | Hoisting | Redeclaration | Recommended use |
| --- | --- | --- | --- | --- |
| `var` | Function scope | Hoisted and initialized to `undefined` | Allowed | Maintaining legacy code |
| `let` | Block scope | Hoisted but not initialized (TDZ) | Not allowed in the same scope | Variables that need reassignment |
| `const` | Block scope | Same as `let` | Not allowed in the same scope | The default choice |

The conclusion is simple: **use `const` by default, switch to `let` when reassignment is needed, and stop using `var`.**

### Temporal Dead Zone (TDZ)

```js
console.log(a); // undefined: the var declaration is hoisted
var a = 1;

console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 2;
```

Block scope also shows up in loops:

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var', i)); // 3 3 3
}

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let', j)); // 0 1 2
}
```

`var` has one shared `i`, while `let` creates a new binding on every iteration.

## Primitive and Reference Types

There are seven primitive types:

- `string`, `number`, `boolean`, `undefined`, `null`, `symbol`, `bigint`

Everything else is an object (`Object`, `Array`, `Function`, `Date`, `Map`, and so on).

```js
typeof 'abc';        // 'string'
typeof 42;           // 'number'
typeof 42n;          // 'bigint'
typeof null;         // 'object' (a historical bug)
typeof undefined;    // 'undefined'
typeof Symbol('s');  // 'symbol'
typeof function () {}; // 'function'
```

Use `value === null` to check for `null`, and `Array.isArray(value)` to check for arrays.

### Values vs. References

```js
let a = 1;
let b = a;
b = 2;
console.log(a); // 1: primitives copy the value

const obj1 = { count: 1 };
const obj2 = obj1;
obj2.count = 2;
console.log(obj1.count); // 2: references copy the address
```

To "copy" an object you need a shallow or deep copy:

```js
const shallow = { ...obj1 };
const deep = structuredClone(obj1); // modern browsers / Node 17+
```

> [!WARNING]
> `const` only guarantees that the **binding** is immutable, not that the object's contents are. After `const obj = {}` you can still do `obj.x = 1`.

## Type Conversion Pitfalls

```js
[] + {};        // '[object Object]'
[] + [];        // ''
null + 1;       // 1
undefined + 1;  // NaN
'5' - 2;        // 3 (minus coerces to number)
'5' + 2;        // '52' (plus prefers string concatenation)
```

How to avoid implicit conversion:

1. Always compare with `===` / `!==`;
2. Convert numbers with `Number(x)` or `parseInt(x, 10)`, and validate with `Number.isNaN`;
3. Convert to boolean with `Boolean(x)`, remembering that `0`, `''`, `null`, `undefined`, and `NaN` are falsy.
