# Duplicate numbers in the array
> Question source: Sword Finger Offer 03. The two questions share the same core: **has a limited value range** - either let the "value" return to the "subscript", or divide it into two parts on the "value range", or treat the array as a directed graph to find loops.
> Convention: Return any repeated number; if it does not exist, return `-1`.

## Differences between questions one and two
### Question 1
Array of length `n`, all elements are in `0..<n`, at least one number is repeated, find any **and**.

The - value range corresponds to the subscript one-to-one: the "correct position" of the number `i` is the subscript `i`;
- Therefore, you can use the **subscript to return to**, and replace each number to the position it should be in;
- allows when modifying the array (such as `inout`), time `O(n)`, extra space `O(1)`;
- Swift array is a value type: `var a = nums`. Exchange will not change the caller, but the space after triggering COW copy is `O(n)`.

### Question 2
Array of length `n+1`, all elements are in `1...n`, at least one number is repeated, find any one, **requires not to modify the array**.

The value range of - is one less than the subscript, and it must be repeated according to the drawer principle;
- cannot be sorted or exchanged. It can only be divided into two parts in the **value range**, or use **Floyd to judge the circle**;
- This is where many people tend to misunderstand: the key restriction in question 2 is "no modification", not "must modify".

## 2. Overview of solutions
| Solution | Time | Space | Modify the original array | Applicable to |
|---|---|---|---|---|
| Violent double cycle | O(n²) | O(1) | No | Entry/small amount of data |
| Hash Set | O(n) | O(n) | No | Universal, most intuitive |
| adjacent comparison after sorting | O(n log n) | O(1)~O(n) | is (or copy) | when sorting is allowed |
| Subscript return | O(n) | O(1) (inout) / O(n) (copy) | is (or copy) | Question 1 |
| Value range divided into two | O(n log n) | O(1) | No | Question 2 |
| Floyd’s judgment circle | O(n) | O(1) | No | Question 2, optimal |

> Ask clearly during the interview: Can **modify the input? Are there any space restrictions? Return any one or the first one?** Different answers correspond to different solutions.

## 3. Question 1: Subscript return
### Ideas
Traverse the array and replace `nums[i]` with the subscript `nums[i]`:
- If `nums[i] == i`, has returned to position, continue;
- If the `nums[i]` position is already the same value, it means a duplicate is found;
- Otherwise swap and continue processing the current position.

### Swift implementation (version without modifying input parameters)
If ```swift
func findDuplicate(_ nums: [Int]) -> Int {
    guard !nums.isEmpty else { return -1 }
    var a = nums                       // 值语义 + COW：不改调用方，但会复制，空间 O(n)
    for i in a.indices {
        while a[i] != i {
            let target = a[i]
            if a[target] == a[i] {     // 目标位置已经是同一个值
                return a[i]
            }
            a.swapAt(i, target)
        }
    }
    return -1
}
```
 is allowed to modify the input parameters directly, `inout` can be used to achieve the real `O(1)` extra space:
```swift
func findDuplicateInPlace(_ nums: inout [Int]) -> Int {
    for i in nums.indices {
        while nums[i] != i {
            let target = nums[i]
            if nums[target] == nums[i] {
                return nums[i]
            }
            nums.swapAt(i, target)
        }
    }
    return -1
}
```
### Correctness
- returns at least one number to the correct position each time it is exchanged, and it can be exchanged at most `n` times;
- If there is duplication, "the target position is already the same value" will inevitably appear at some point;
- If the traversal is not found yet, it means there is no duplication.

### Complexity
- time `O(n)`: Each element is exchanged at most once;
- space: The version without modifying the input parameters is `O(n)` (COW copy); the `inout` version is `O(1)`.

> If question 1 requires "not modifying the array", then subscript return is not applicable and the hash Set or sorted copy will be returned.

## 4. Question 2: Value range divided into two points
### Ideas
Do not bisect the subscript, bisect the **number range** `[1, n]`:
1. takes the midpoint `mid`, and counts the number of numbers `count` that falls in `[low, mid]` in the array;
2. If `count > mid - low + 1`, it means that the repeated number is in the left half of the interval;
3. otherwise in the right half interval;
4. The interval is reduced to only one number, which is the answer.

### Swift implementation
```swift
func findDuplicateBinarySearch(_ nums: [Int]) -> Int {
    guard nums.count >= 2 else { return -1 }

    var low = 1
    var high = nums.count - 1          // 值域上界 n
    while low < high {
        let mid = low + (high - low) / 2
        let count = nums.reduce(0) { partial, value in
            partial + ((value >= low && value <= mid) ? 1 : 0)
        }
        if count > mid - low + 1 {
            high = mid                 // 重复在左半
        } else {
            low = mid + 1              // 重复在右半
        }
    }
    return low
}
```
### Complexity
- time `O(n log n)`: two `log n` rounds, each round scans the array;
- space `O(1)`, does not modify the array.

### Error-prone points
- `high` is the upper bound of the **value range** `n = nums.count - 1`, not the upper bound of the subscript;
The statistical range of - is `[low, mid]`, not `[0, mid]`;
The question - is guaranteed to be repeated, so at the end of the loop `low == high` is the answer; if there is no repetition, additional verification is required.

## 5. Question 2: Floyd’s circle judgment (optimal)
### Idea
Think of the array as a directed graph: subscript `i` points to `nums[i]`.
- Because the value range is `1...n` and the length is `n+1`, starting from subscript 0 will definitely enter the ring;
The entrance to the - ring is a repeated number (two subscripts point to the same value).

### Swift implementation
```swift
func findDuplicateFloyd(_ nums: [Int]) -> Int {
    guard nums.count >= 2 else { return -1 }

    var slow = nums[0]
    var fast = nums[0]

    repeat {
        slow = nums[slow]              // 走一步
        fast = nums[nums[fast]]        // 走两步
    } while slow != fast

    slow = nums[0]                     // 一个指针回到起点
    while slow != fast {
        slow = nums[slow]
        fast = nums[fast]
    }
    return slow
}
```
### Complexity
- time `O(n)`;
- space `O(1)`;
- does not modify the array, which is the optimal solution to question 2.

### Prerequisite
- array length `n+1`, value range `1...n`, ensure `nums[i]` is a legal subscript;
- If the value range contains `0` or may be out of bounds, this mapping is not established and cannot be used directly.

## 6. Other solutions
### 1. Hash Set
```swift
func findDuplicateSet(_ nums: [Int]) -> Int {
    var seen = Set<Int>()
    for value in nums {
        if !seen.insert(value).inserted {
            return value
        }
    }
    return -1
}
```
- time `O(n)`, space `O(n)`;
- is the most intuitive and suitable for scenarios where it is not the best solution for interviews but is sufficient for engineering.

### 2. Sorting
```swift
func findDuplicateSort(_ nums: [Int]) -> Int {
    let sorted = nums.sorted()
    guard sorted.count >= 2 else { return -1 }
    for i in 1..<sorted.count where sorted[i] == sorted[i - 1] {
        return sorted[i]
    }
    return -1
}
```
 - time `O(n log n)`, space depends on whether in-place sorting is allowed;
- will disrupt the order of the original array, and what is returned is not necessarily the "first" repeated value.

### 3. Violence
```swift
func findDuplicateBruteForce(_ nums: [Int]) -> Int {
    for i in 0..<nums.count {
        for j in (i + 1)..<nums.count where nums[i] == nums[j] {
            return nums[i]
        }
    }
    return -1
}
```
- time `O(n²)`, space `O(1)`;
- is only suitable for teaching or very small data volumes.

## 7. Test cases
```swift
func check(_ actual: Int, _ expected: Set<Int>) {
    assert(expected.contains(actual), "got \(actual), expected one of \(expected)")
}

// 题目一：0..<n
check(findDuplicate([2, 3, 1, 0, 2, 5, 3]), [2, 3])
check(findDuplicate([1, 1]), [1])
check(findDuplicate([0, 0, 1]), [0])

// 题目二：1...n，长度 n+1
check(findDuplicateBinarySearch([2, 3, 5, 4, 3, 2, 6, 7]), [2, 3])
check(findDuplicateFloyd([2, 3, 5, 4, 3, 2, 6, 7]), [2, 3])
check(findDuplicateFloyd([1, 1]), [1])
check(findDuplicateFloyd([3, 3, 3, 3]), [3])
```
 recommends covering:
- empty array / only one element;
- repeated values at the beginning, end, and middle;
- Multiple duplicate values (the return value only needs to belong to the set);
- All elements are the same;
The maximum value of - in question 2, `n`, appears at the boundary.

## 8. Common pitfalls
1. ❌ `for i in 0...nums.count-1`: Empty arrays will collapse due to `0...-1`, use `indices` or judge empty first;
2. ❌ The subscript is out of bounds during recursion/exchange: Question 1 must ensure that the value range is in `0..<n`, question 2 must be in `1...n`;
3. ❌ Sorting or exchanging in question 2: Violating the restriction of "not modifying the array";
4. ❌ The value range is divided into two subscripts: the statistics are "the number of numbers falling within the interval", not the "subscript interval";
5. ❌ Floyd is directly applied to question one: the value range of question one contains `0`. If `nums[0] == 0`, starting from subscript 0, it will fall into a self-loop and return 0; Floyd is only suitable for the constraints of question two such as `1...n` and length `n+1`;
6. ❌ It is believed that the return value must be "the first recurring number": the question only requires any one, and do not write down the order in the test.

## 9. Summary
- The key to question one is that the subscript of **returns to**: the value range and the subscript coincide with each other and can be exchanged;
The key to the second question of - is that **does not modify**: either divide it into two parts in the value range, or use Floyd to judge the circle;
- Prioritizes readability (Set/Sort) in the project, and then selects the optimal solution based on restrictions during the interview;
- Confirming the constraints first and then writing the code is more important than memorizing the solution.
