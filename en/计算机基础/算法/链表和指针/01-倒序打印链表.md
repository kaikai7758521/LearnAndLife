# Print linked list in reverse order
> Question: Given a singly linked list, print the value of each node from the end to the beginning.
> Key: Recursion can "borrow the call stack" to achieve reverse order, but the depth is limited by the length of the linked list; reversing the linked list can achieve `O(1)` extra space, but will change the original structure; the explicit stack is a compromise that does not change the structure and is not afraid of depth.

## 1. Node definition
```swift
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, _ next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}
```
> only requires "printing" and does not require returning a new linked list; if the question requires returning an array, just replace `print` with `append`. The idea is exactly the same.

## 2. Solution 1: Recursion
```swift
func printListReversed(_ head: ListNode?) {
    guard let node = head else { return }
    printListReversed(node.next)   // 先递归到尾部
    print(node.value)              // 回溯时打印，天然倒序
}
```
### Analysis
- time `O(n)`;
- space `O(n)`: recursive call stack, the depth is equal to the length of the linked list;
- does not modify the linked list and has the shortest code.

### Risk
- When the linked list is very long (more than tens of thousands of nodes), the **stack may overflow**;
- The recursion here is not tail recursion, and Swift does not guarantee tail recursion optimization;
- If there is a loop in the linked list, the recursion will never reach the end and the stack will overflow directly.

> Common mistake: Forgetting to call `next` inside the recursive function will call itself infinitely; the above `printListReversed(node.next)` is the correct way to move forward.

## 3. Solution 2: Explicit stack (recommended)
```swift
func printListReversedStack(_ head: ListNode?) {
    var stack: [Int] = []
    var node = head

    while let current = node {
        stack.append(current.value)
        node = current.next
    }

    while let value = stack.popLast() {
        print(value)
    }
}
```
### Analysis
- time `O(n)`;
- space `O(n)`, but is allocated on the heap and is not limited by the call stack depth;
- does not modify the linked list, which is the safest in the project.

### Applicable
- The length of the linked list is uncontrollable;
The - linked list may be shared by other codes, and the structure cannot be changed;
- needs to collect the results into an array and return it.

## 4. Solution 3: Reverse the linked list and print again
```swift
func reversed(_ head: ListNode?) -> ListNode? {
    var prev: ListNode?
    var current = head

    while let node = current {
        let next = node.next
        node.next = prev
        prev = node
        current = next
    }
    return prev                    // 注意：返回 prev，不是 current
}

func printListReversedByReverse(_ head: ListNode?) {
    var node = reversed(head)
    while let current = node {
        print(current.value)
        node = current.next
    }
}
```
### Analysis
- time `O(n)`;
- extra space `O(1)`;
- will **modify the original linked list**: If the original head node is still held externally, its `next` has been rewritten.

### When the original structure needs to be maintained
After printing, reverse it again to recover:

```swift
let newHead = reversed(head)
// 打印 newHead ...
let restoredHead = reversed(newHead)   // 恢复后的头节点
// 之后从 restoredHead 开始遍历（通常就是原来的 head）
```

> The concurrent read scenario is still unsafe: other threads will see the structure changes during the reversal and must lock or use an explicit stack instead.

The most common clerical error when reversing > is the last `return current`, while at the end of the loop `current` is already `nil` and should return `prev`.

## 5. Solution 4: Build a new linked list with head insertion method (optional)
If you are not allowed to modify the original linked list and you want to write iteratively, you can create a new node:
```swift
func reversedCopy(_ head: ListNode?) -> ListNode? {
    var newHead: ListNode?
    var node = head
    while let current = node {
        newHead = ListNode(current.value, newHead)  // 头插
        node = current.next
    }
    return newHead
}
```
- time `O(n)`, space `O(n)`;
- The original linked list is completely unchanged, but there is an extra node memory;
- is suitable for the scenario of "printing/returning the results in reverse order while retaining the original linked list".

## 6. Scheme comparison
| Solution | Time | Extra space | Modify the original linked list | Main risks |
|---|---|---|---|---|
| Recursion | O(n) | O(n) Call stack | No | Long linked list stack overflow |
| Explicit stack | O(n) | O(n) Heap memory | No | Memory occupied |
| reverses | O(n) | O(1) | **is** | destroys the shared linked list and needs to be restored |
| Header insertion to create a new linked list | O(n) | O(n) | No | Additional node overhead |

Selection suggestions:
1. only prints, the length is controllable → recursive;
2. The length is uncontrollable and the structure cannot be changed → explicit stack;
3. explicitly allows structure modification and pursues `O(1)` space → inversion;
4. Wants to iterate but does not want to change the original linked list → Create a new linked list at the beginning.

## 7. Boundaries and testing
### Boundary to be covered
- Empty linked list: do not print, return directly;
- single node: print once;
- Two nodes: the order is tail → head;
- Very long linked list: Verify whether recursion will cause stack overflow;
- Ring linked list: Recursion/iteration will lead to an infinite loop, so you need to first determine the ring or limit the number of steps.

### Uses array return value for testing
It is inconvenient to directly assert the output of `print`. Use a version that returns an array when testing:
If ```swift
func reversedValues(_ head: ListNode?) -> [Int] {
    var stack: [Int] = []
    var node = head
    while let current = node {
        stack.append(current.value)
        node = current.next
    }
    return stack.reversed()
}

// 构建 1 -> 2 -> 3
let list = ListNode(1, ListNode(2, ListNode(3)))
assert(reversedValues(list) == [3, 2, 1])
assert(reversedValues(nil) == [])
assert(reversedValues(ListNode(7)) == [7])
```
 must verify the print result, `print` can be extracted into a closure and injected:
```swift
func traverseReversed(_ head: ListNode?, visit: (Int) -> Void) {
    var stack: [Int] = []
    var node = head
    while let current = node {
        stack.append(current.value)
        node = current.next
    }
    while let value = stack.popLast() {
        visit(value)
    }
}
```
 is passed in the test like this `{ values.append($0) }` That’s it.

## 8. Common pitfalls
1. ❌ The recursive function is not called `next`: It will recurse infinitely until the stack overflows;
2. ❌ Return `current` after inversion: it is `nil` at the end of the loop and should return `prev`;
3. ❌ `print(node?.value)`: `Optional(1)` will be printed and should be unpacked first;
4. ❌ Forgot to restore after reversal: the linked list structure obtained by the caller has been destroyed;
5. ❌ It is believed that recursion saves space than the explicit stack: the call stack is also `O(n)`, and is more likely to overflow;
6. ❌ If there is a loop in the linked list, directly use any of the above solutions: there is no termination condition, the loop must be determined or the number of steps must be limited;
7. ❌ Use `0...count-1` to traverse: an empty linked list will cross the boundary, so `while let` should be used for linked list traversal.

## 9. Summary
- The essence of "reverse printing" is **last in first out**: the call stack, explicit stack, and reversed forward traversal are all different implementations of the same thing;
- recursion is the simplest, but the depth is uncontrollable;
- explicit stack is the most stable and is recommended as the default solution for projects;
- Inversion saves the most space, but it will change the structure and the ownership must be clear;
- First ask, "Can the linked list be modified and what is its approximate length?" and then choose a solution.
