# 倒序打印链表
> 题目：给定一个单链表，从尾到头打印每个节点的值。
> 关键：递归可以「借用调用栈」实现倒序，但深度受限于链表长度；反转链表能做到 `O(1)` 额外空间，却会改变原结构；显式栈是不改结构且不怕深度的折中方案。

## 一、节点定义
```swift
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, _ next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}
```
> 只要求「打印」，不要求返回新链表；如果题目要求返回数组，把 `print` 换成 `append` 即可，思路完全一样。

## 二、解法一：递归
```swift
func printListReversed(_ head: ListNode?) {
    guard let node = head else { return }
    printListReversed(node.next)   // 先递归到尾部
    print(node.value)              // 回溯时打印，天然倒序
}
```
### 分析
- 时间 `O(n)`；
- 空间 `O(n)`：递归调用栈，深度等于链表长度；
- 不修改链表，代码最短。

### 风险
- 链表很长（几万个节点以上）时可能**栈溢出**；
- 这里的递归不是尾递归，Swift 也不保证尾递归优化；
- 如果链表有环，递归永远到不了尾部，直接栈溢出。

> 常见错误：递归函数内部忘记调用 `next`，会无限调用自身；上面的 `printListReversed(node.next)` 才是正确的前进方式。

## 三、解法二：显式栈（推荐）
```swift
func printListReversedStack(_ head: ListNode?) {
    var stack: [Int] = []
    var node = head

    while let current = node {
        stack.append(current.value)
        node = current.next
    }

    while let value = stack.popLast() {
        print(value)
    }
}
```
### 分析
- 时间 `O(n)`；
- 空间 `O(n)`，但分配在堆上，不受调用栈深度限制；
- 不修改链表，工程里最稳妥。

### 适用
- 链表长度不可控；
- 链表可能被其他代码共享，不能改结构；
- 需要把结果收集成数组返回。

## 四、解法三：反转链表再打印
```swift
func reversed(_ head: ListNode?) -> ListNode? {
    var prev: ListNode?
    var current = head

    while let node = current {
        let next = node.next
        node.next = prev
        prev = node
        current = next
    }
    return prev                    // 注意：返回 prev，不是 current
}

func printListReversedByReverse(_ head: ListNode?) {
    var node = reversed(head)
    while let current = node {
        print(current.value)
        node = current.next
    }
}
```
### 分析
- 时间 `O(n)`；
- 额外空间 `O(1)`；
- 会**修改原链表**：如果外部还持有原头节点，它的 `next` 已经被改写。

### 需要保持原结构时
打印完再反转一次即可恢复：

```swift
let newHead = reversed(head)
// 打印 newHead ...
let restoredHead = reversed(newHead)   // 恢复后的头节点
// 之后从 restoredHead 开始遍历（通常就是原来的 head）
```

> 并发读场景仍不安全：反转过程中其他线程会看到结构变化，必须加锁或改用显式栈。

> 反转最常见的笔误是最后 `return current`，而循环结束时 `current` 已经是 `nil`，应返回 `prev`。

## 五、解法四：头插法构建新链表（可选）
如果不允许修改原链表，又想要迭代写法，可以新建节点：
```swift
func reversedCopy(_ head: ListNode?) -> ListNode? {
    var newHead: ListNode?
    var node = head
    while let current = node {
        newHead = ListNode(current.value, newHead)  // 头插
        node = current.next
    }
    return newHead
}
```
- 时间 `O(n)`，空间 `O(n)`；
- 原链表完全不动，但多了一份节点内存；
- 适合「打印/返回倒序结果，同时保留原链表」的场景。

## 六、方案对比
| 方案 | 时间 | 额外空间 | 修改原链表 | 主要风险 |
|---|---|---|---|---|
| 递归 | O(n) | O(n) 调用栈 | 否 | 长链表栈溢出 |
| 显式栈 | O(n) | O(n) 堆内存 | 否 | 占内存 |
| 反转 | O(n) | O(1) | **是** | 破坏共享链表，需恢复 |
| 头插建新链表 | O(n) | O(n) | 否 | 额外节点开销 |

选择建议：
1. 只打印、长度可控 → 递归；
2. 长度不可控、不能改结构 → 显式栈；
3. 明确允许改结构且追求 `O(1)` 空间 → 反转；
4. 既要迭代又不想动原链表 → 头插建新链表。

## 七、边界与测试
### 需要覆盖的边界
- 空链表：不打印，直接返回；
- 单节点：打印一次；
- 两节点：顺序为尾 → 头；
- 超长链表：验证递归是否会栈溢出；
- 有环链表：递归/迭代都会死循环，需先判环或限制步数。

### 用数组返回值做测试
直接断言 `print` 的输出不方便，测试时用一个返回数组的版本：
```swift
func reversedValues(_ head: ListNode?) -> [Int] {
    var stack: [Int] = []
    var node = head
    while let current = node {
        stack.append(current.value)
        node = current.next
    }
    return stack.reversed()
}

// 构建 1 -> 2 -> 3
let list = ListNode(1, ListNode(2, ListNode(3)))
assert(reversedValues(list) == [3, 2, 1])
assert(reversedValues(nil) == [])
assert(reversedValues(ListNode(7)) == [7])
```
如果必须验证打印结果，可以把 `print` 抽成闭包注入：
```swift
func traverseReversed(_ head: ListNode?, visit: (Int) -> Void) {
    var stack: [Int] = []
    var node = head
    while let current = node {
        stack.append(current.value)
        node = current.next
    }
    while let value = stack.popLast() {
        visit(value)
    }
}
```
这样测试里传 `{ values.append($0) }` 即可。

## 八、常见坑
1. ❌ 递归函数没有调用 `next`：会无限递归，直到栈溢出；
2. ❌ 反转后返回 `current`：循环结束时它是 `nil`，应返回 `prev`；
3. ❌ `print(node?.value)`：会打印 `Optional(1)`，应先解包；
4. ❌ 反转后忘记恢复：调用方拿到的链表结构已经被破坏；
5. ❌ 认为递归比显式栈省空间：调用栈同样是 `O(n)`，而且更易溢出；
6. ❌ 链表有环时直接用上述任一方案：没有终止条件，必须判环或限制步数；
7. ❌ 用 `0...count-1` 之类的方式遍历：空链表会越界，链表遍历应使用 `while let`。

## 九、总结
- 「倒序打印」的本质是**后进先出**：调用栈、显式栈、反转后的正向遍历，都是同一件事的不同实现；
- 递归最简洁，但深度不可控；
- 显式栈最稳，推荐作为工程默认方案；
- 反转最省空间，但会改结构，必须明确所有权；
- 先问清楚「能不能修改链表、长度大概多少」，再选解法。
